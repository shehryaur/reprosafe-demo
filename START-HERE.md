# ReproSafe: Click-by-Click Guide

## What You Have

A working local application, not a slide deck or a simulated security dashboard.

ReproSafe takes a small Python bug and its private JSON input, reproduces the failure in Wasmer, constructs replacement data, and checks whether the replacement still triggers the same failure. Human-review mode shows the exact proposed Gemini or Claude request before anything is sent. Optional automatic mode uses explicit permission for that one run. A proposed fix is checked locally against the original input, synthetic input, and two regression cases. Google Gemini API is the default provider; Anthropic remains available in Settings.

The current product handles two explicit contracts: case-sensitive invoice customer isolation and quoted CSV import. It can read selected GitHub Python/JSON files and bounded Supabase table rows mapped to those formats. It does not diagnose arbitrary repositories, PDFs, database queries, or every kind of Python bug.

**New: GitHub, Supabase, public transaction demo, and Auto:** follow [CONNECTED-SOURCES.md](CONNECTED-SOURCES.md). The public dataset and exact upload steps are in [demo/retail/README.md](demo/retail/README.md). Actual comparison measurements are in [benchmark-results/COMPARISON.md](benchmark-results/COMPARISON.md).

## 1. Open the Product

On this computer, setup has already been performed. Start with:

**[Open ReproSafe with connected sources and Auto](http://127.0.0.1:4319)**

Earlier sessions on ports 4317/4318 were left running so their memory-only settings were not discarded. This updated instance uses port 4319. Connections are separate between instances, so enter your Gemini key again in the updated app. On future launches, use the address opened by Start-ReproSafe.cmd; the default on a fresh machine is 4317.

If that address is unavailable:

1. Open the `reprosafe` folder containing this guide in File Explorer.
2. Double-click **Start-ReproSafe.cmd**.
3. Wait for your browser to open. The launcher reuses a running instance or starts a new one. If the default port is occupied, it uses another local port and opens the correct address.
4. You should see **Invoice customer isolation**, a source editor, and an execution results panel.

There is no Wasmer dashboard deployment step. The app uses the real Wasmer SDK directly on this machine. Your Wasmer account token is not needed for this local workflow. Tenki is not used or charged by this app. The official [Wasmer JavaScript SDK documentation](https://docs.wasmer.io/runtime/js/) covers the underlying runtime.

Keep this folder intact. Do not delete `node_modules`, `.wasmer`, or `dist` before your presentation.

## 2. Check Wasmer Before the Demo

1. Click the **settings sliders icon** in the upper-right corner.
2. Under **Wasmer runtime**, click **Check runtime**.
3. Wait for **Python execution verified**.
4. Click **Close**.

The runtime package is about 157 MB. It is already cached on this machine. A fresh machine needs an internet connection for the first download. Later runs load the cached package directly after checking its SHA-256, without refreshing the Wasmer registry. Individual sandbox executions also have startup overhead. Warm up before judging, not during your opening sentence.

You do not need to install Python, Rust, Docker, or a separate Wasmer command-line tool.

## 3. Rehearse Without Paying for an AI Call

This route exercises the real sandbox and validation system. Its fix is explicitly labeled as a bundled sample, not generated by AI.

1. Click **Invoice customer isolation** in the left sidebar.
2. Click the **Private input** tab. Notice the two customer IDs, `ACCT-NOVA` and `acct-nova`. They are different customers under this contract. All names and addresses in this demonstration are made-up sample data.
3. Click **Source code**. The bug is the `.lower()` call: it changes both customer identifiers into the same key.
4. Click **Reproduce failure** at the bottom-right.
5. Wait for **Failure reproduced** and `CUSTOMER_ISOLATION`. This is the actual result of running Python inside Wasmer.
6. Click **Create synthetic case**.
7. Wait for two candidate results. **Ordinary value masking** loses the original failure. **Preserve customer ID case relationships** keeps it, using replacement identifiers, invoices, names, addresses, and amounts.
8. Click **Review outgoing request**.
9. Scroll through the entire request. It contains the source, acceptance contract, synthetic input, and a bounded failure description. The original fixture and execution logs are absent.
10. Click **Continue without AI**. Nothing is sent to a model provider.
11. Click **Load bundled sample fix** below the empty patch panel.
12. Inspect **Changes**. The fix removes `.lower()`.
13. Click **Validate patch**.
14. Wait for **4 / 4 passed**. The four checks are the private original, verified synthetic input, repeated-customer regression, and case-sensitive/zero-amount regression.
15. Click **Export reproduction**. Your browser downloads a ZIP containing the synthetic reproducer and validated fix.

The main point is not that AI can delete `.lower()`. It is that a failure-preserving replacement fixture can support debugging without sending the original customer records to the model.

## 4. Connect Gemini for a Live AI Patch

Only you need to do this step. Do not put your API key in the chat, source code, screenshots, or exported ZIP.

1. Open the official [Google AI Studio API keys page](https://aistudio.google.com/apikey).
2. Sign in to your Google account. Google AI Pro sign-in itself is not an API key.
3. Create a Gemini API key for a Google Cloud project you control. For an existing Cloud Console project, import it into AI Studio first if it is not listed. Use a key authorized for the Generative Language API, not an unrelated Google service or a Vertex-only credential. See [Google's key setup](https://ai.google.dev/gemini-api/docs/api-key).
4. Copy the key once. Requests use that project's Gemini API quota and billing; check the [API billing settings](https://ai.google.dev/gemini-api/docs/billing).
5. Return to ReproSafe. Click the **settings sliders icon**, then select **Google Gemini API** under **Provider**.
6. Paste the key into **Gemini API key**.
7. Click **Load available models**. This requests model metadata from Google, not your case data. The app follows all returned catalog pages and filters for Gemini text-generation candidates.
8. Choose a model in **Model**. The list comes from Google's API, not a hard-coded model name. A catalog entry is not a guarantee of quota or JSON-output support; those are checked on the approved generation request.
9. Click **Save settings**. The header should read **Gemini configured**. That label means the key and model are configured, not that a patch has already succeeded.
10. Run steps 1-8 of the invoice rehearsal again, or prepare a fresh outgoing request for the existing case.
11. Inspect the complete request, including source comments and literals.
12. Confirm the destination is `generativelanguage.googleapis.com`, then check **I reviewed this exact request and approve sending it to Gemini**.
13. Click **Send approved request**.
14. Wait for the patch. Inspect **Changes** or **Patch editor** before running it.
15. Click **Validate patch**. A model response is only a proposal; it is not automatically correct.
16. Export once all four checks pass.

The key is held in local server memory by default and cleared when the server stops. No request is automatically retried. Gemini has an 8,192-token output budget, which can also be consumed by model reasoning. Truncated responses are rejected. API billing is separate from running the local app; do not assume a chat subscription or sponsor credit pays for these calls.

If Gemini returns invalid JSON, times out, is blocked, or proposes a failing patch, the app reports that result. It does not silently replace it with the bundled fix. You can make a separately approved retry or enter a manual patch.

To retain the original Claude workflow, choose **Anthropic Claude API**, enter an [Anthropic key](https://platform.claude.com/settings/keys), load models, select one, and save. Keys and model selections are kept separately for each provider. Claude retains its 2,400-token output budget. Switching provider, model, or key invalidates earlier request previews. There is no Antigravity proxy integration; both providers connect to their official endpoints.

## 5. Show the Second Use Case

1. Click **Quoted CSV import** in the sidebar. Switching examples clears the previous local case.
2. Look at **Private input**. One name contains a comma inside quotation marks.
3. Click **Reproduce failure**. Expect `CSV_PARSE_ERROR`.
4. Click **Create synthetic case**. Plain replacement names hide the parsing bug; preserving a quoted comma keeps it.
5. Review the outgoing request and choose either the live model flow or **Continue without AI** followed by **Load bundled sample fix**.
6. Click **Validate patch**. The corrected module uses Python's standard CSV parser.

This demonstrates that ReproSafe is checking behavior, not just replacing names with generic text.

## 6. Prove That a Fake Fix Does Not Pass

1. Finish generating a synthetic case.
2. Open **Review & patch**.
3. Choose **Enter patch**, or open **Patch editor** if a patch is already loaded.
4. Replace the patch with:

```python
def process(records):
    return []
```

5. Click **Validate patch**.
6. All four checks should fail. Hiding the data is not a valid fix.
7. To return to the clean demonstration, select the same sidebar example again and repeat the rehearsal.

## 7. Use Your Own Authorized Case

Start with synthetic data, not real customer information, while learning the tool.

1. Click **New case** in the sidebar. On a narrow screen, first click the folder icon next to ReproSafe.
2. Enter a case name.
3. Choose **Invoice customer isolation** or **Quoted CSV import** as the acceptance contract.
4. Click **Create case**.
5. In **Source code**, enter one Python module with a `process(records)` function. Alternatively, click the upload arrow next to the file label and select a `.py` file.
6. In **Private input**, enter a JSON array or import a `.json` file with that tab's upload arrow.
7. Open **Contract** and check that your input and expected output actually match it.
8. Click **Reproduce failure**. Then follow the same generate, review, patch, and validate flow.

Invoice input accepts `customer_id`, `invoice_id`, `amount_cents`, and optional `name`, `email`, `notes`. Invoice IDs must be unique. Amounts are nonnegative integers in cents. CSV input accepts `row` and optional `reference`; each row is valid CSV with exactly a name and a nonnegative integer amount.

Limits: 60 records, 24,000 source characters, standard-library-only Python, and the schemas shown in the Contract tab. No package installation, network calls, database connections, or host directory mounts are provided to the guest.

An unsupported failure can produce **No releasable reproducer found**. That is an honest outcome, not a broken success indicator. This version tries two bounded replacement strategies; it does not solve arbitrary test-case synthesis.

## 8. Understand the Download

The downloaded ZIP contains:

| File | Purpose |
| --- | --- |
| `main.py` | Reviewed original source with the bug |
| `input.json` | Verified synthetic input only |
| `verify.py` | Standalone acceptance checks |
| `model-request.json` | Prepared request body, without credentials |
| `model-request-meta.json` | Provider, model, exact destination, and approval hash |
| `report.json` | Failure category, strategy, payload hash, and validation results |
| `fixed.py` | Included only after all four checks pass and the patch passes the release scan |
| `README.txt` | Instructions for running the reproducer |

Review exported source before sharing it. The request hash identifies the provider, model, destination, and prepared body together; it is not a cryptographic signature or proof that a model call occurred.

In an appropriate isolated Python environment, `python verify.py main` should fail and `python verify.py fixed` should pass. Do not execute unfamiliar exported code directly on a sensitive machine.

## 9. Start From Scratch on Another Windows Computer

1. Download the `ReproSafe-source.zip` delivered alongside this folder.
2. Right-click it in File Explorer and choose **Extract All**. Choose a local folder you can write to.
3. Open the extracted `reprosafe` folder. Do not run the launcher from inside the ZIP viewer.
4. Open the official [Node.js download page](https://nodejs.org/en/download).
5. Install Node.js **24 or newer**, selecting the Windows installer matching your computer. Keep npm and the default PATH option enabled. Administrator mode is not required for ReproSafe itself.
6. Reopen File Explorer after installation and double-click **Start-ReproSafe.cmd**.
7. Wait for dependency installation and the production build. This requires internet access. A failed step stays visible in the launcher window.
8. Once the browser opens, use **Settings > Check runtime** to download and test Python.
9. If a slow connection exceeds the in-app initialization deadline, right-click the app folder and select **Open in Terminal**, then run `npm run check:runtime`. This diagnostic allows up to ten minutes for initialization. Retry the UI check afterward.
10. Rehearse without AI, then configure your Gemini or Claude API key if needed.

For a developer working in the source folder, the equivalent commands are:

```powershell
npm ci
npm run build
npm run check:runtime
npm start
```

Use `npm run dev` while editing. After changing code for the production launcher, stop the server, run `npm run build`, and start it again. Launchers do not automatically rebuild an existing production bundle on every launch.

## 10. Troubleshooting

| What you see | What to do |
| --- | --- |
| Browser cannot connect | Double-click Start-ReproSafe.cmd. Use the address it opens, which may have a different port. |
| Browser works but the app reports access denied / EACCES | The local server's process is blocked from networking; this is not proof of bad Wi-Fi or a bad key. Grant the execution environment network access. On your own Windows machine, launch Restart-ReproSafe.cmd from File Explorer to use your normal desktop permissions, then re-enter the memory-only API key. Do not disable certificate checks or your firewall. |
| Node is not recognized | Install Node 24+, reopen File Explorer or your terminal, and start again. |
| Runtime check fails | Check internet access and run `npm run check:runtime`. Keep `.wasmer` so successful downloads are reused. |
| Contract passed on original | Your current input does not demonstrate a supported failure. Check the chosen example and source. |
| No releasable reproducer | The available strategies did not preserve the failure or source contains a blocked private value. Review the displayed result; do not force a release. |
| Input does not match contract | Check exact field names, unique invoice IDs, integer amounts, array shape, and the record limit. |
| Model list fails | Check the selected provider, API key, project access, restrictions, quota, and connection. No case data is sent by model listing. |
| Google rejects the key | Create a current Gemini key in AI Studio for the intended Cloud project. Check Generative Language API access and any key restrictions. |
| Google reports a quota limit | Check the API project's usage and billing in AI Studio. A Google AI Pro subscription is not a substitute for project API access. No automatic retry is made. |
| Send button is disabled | Configure key and model, prepare a fresh preview, and check the explicit approval box. |
| Model selection changed | Close the old request and click Review outgoing request again. Approval is tied to the exact model and payload. |
| Patch fails tests | Inspect the changed lines and failed checks. Retry with explicit approval or edit the patch manually. |
| Export blocked by private value | Remove embedded private values or credentials from the patch, validate again, and retry. |
| Old session error | Reload the page after restarting the server, then reproduce the case again. |

Click **Cancel** during a case execution to terminate its worker. An interrupted validation is not treated as a complete pass.

**Restart-ReproSafe.cmd** stops the current instance and starts it again on the same port where possible. It clears in-memory cases and keys. A server launched by a restricted coding environment may keep those process restrictions even when a separate diagnostic command is later granted network access. Start it from your normal desktop launcher for regular use, subject to your computer's security policy.

## 11. What to Say to the Judges

Opening: "A customer reports a bug that only happens on their data. Sending those records to a coding model is risky, but ordinary redaction can erase the bug. ReproSafe checks that a replacement fixture still reproduces the failure before you release it."

Show the original failing, ordinary masking losing the failure, and structure-preserving replacement retaining it. Then show the exact outgoing request, a reviewed patch, and four local validation results.

Wasmer explanation: "Every original run, candidate run, and patch check executes in a fresh local Wasmer sandbox. Guest networking is disabled. The sandbox receives no model key and no mounted host workspace."

Scope statement: "This is a working prototype for two data-processing contracts, not a universal anonymization guarantee."

Show genuine progress honestly. Disclose prebuilt code and prerecorded material if used, and confirm the event's rules about work done before the hackathon. Do not claim the bundled sample patch came from a live AI call.

## 12. Stop, Privacy, and Boundaries

Double-click **Stop-ReproSafe.cmd** when finished. Closing the browser alone does not stop the server. Case data and keys are held in memory; the app expires inactive cases after about an hour. Changing source/input, resetting, or switching examples discards that case's results. Browser reload starts a fresh UI, not a saved project history.

What goes out: public runtime downloads during setup; Google or Anthropic model metadata requests when you click Load available models; and the exact reviewed request body when you approve Send. Authentication and ordinary transport headers accompany API calls. Google keys are sent in the `x-goog-api-key` header, not in request URLs. No private fixture, guest logs, or replacement map is added to the model request.

What is stored on disk: application code and dependencies, public runtime cache, public server startup metadata, and exports you deliberately download. The default app does not write uploaded fixtures to disk. This is not a secure-erasure claim: OS paging, crash dumps, browser extensions, malicious local software, and anything you independently copy or export remain outside that guarantee. The optional `.env` path is a deliberate persistent-key option for developers, not the default UI path.

The scanner checks original string values of at least four characters, parsed CSV names, and a few recognizable credential patterns. It does not detect every secret, numeric coincidence, encoded value, short identifier, or re-identification through preserved structure. Source code itself is included in the reviewed artifact. Review it carefully.

The application is single-user and loopback-only. It has no hosted authentication, tenant isolation, OS-enforced total-memory quota, external security audit, or production compliance certification. Deadlines, bounded outputs, and a worker heap cap are useful controls, not a complete defense against every hostile program. Use only authorized examples on a non-sensitive demo machine. Do not publish this server through a tunnel or run arbitrary internet-submitted code.

For this hackathon, keep the private runner local. A later Tenki-hosted service should receive only explicitly approved artifacts and needs a separate multi-user security design.
